## 6. 数のイメージを育てる前段階（I・追加 2026-11-24）

### ねらい

計算の手順（「7を2と5に分けて…」）の前に、**10や5のかたまりを頭の中に思い浮かべて、数を動かせる**ようにしたい。次のようなつまずきがあるときに効く仕掛けをまとめました。

- 「8にいくつで10」がすぐに出ない
- 13−12 のように、1しか差がない引き算で悩む
- 7＋5を「5と2に分けて」と言葉で説明されても、ピンと来ない

### Claudeの見立て

今のアプリは、間違えたときの補助問題が「7は 2と いくつ？」のような**数字の問い**です。図（10の枠）も、答えを確かめるために**止まった絵**として出るだけです。そのため、「数を分ける・寄せる」場面を目で見たり手で動かしたりする前に、数字だけで考える段階に進んでいます。

足りないのは、次の3つの体験だと考えます。

1. **かたまりを見て、すぐ分かる**：8は「5と3」の形、10まで「あと2」は白い2つ、と数えずに分かる
2. **丸を自分で動かす**：7＋5なら、5のうち2個を前の枠に寄せると10ができる。「分ける」は、言葉ではなく「動かした結果」として見る
3. **数どうしの近さを見る**：13と12は数の線でとなり同士。「とる」より「いくつ ちがう？」と見るほうが楽な引き算がある

以下の I-1〜I-5 は、すべて20以内・10のまとまり中心の範囲におさまります。制限時間も足しません。

| 優先 | 項目 | おすすめ | ひとことで |
|:-:|---|---|---|
| ★★★ | I-1 10の枠を見て答える問題 | **採用** | 数字より先に「形」で答える |
| ★★★ | I-2 丸を自分で動かす補助 | **採用** | 「2個うつすと10になった」を手で体験する |
| ★★☆ | I-3 となりの数のちがい | **採用** | 1しか差がない引き算の前段階 |
| ★★☆ | I-5 家でできること | **すぐ（アプリの変更なし）** | 卵パック・指・10円玉 |
| ★☆☆ | I-4 5のまとまりで考える足し算 | **要相談** | 学校の足し算の教え方とそろえる確認が必要 |

### I-1 ★★★ 10の枠を見て答える問題

**今の作り**：LEVEL 1の「あといくつで10」は、`8 ＋ □ ＝ 10` という式が先に出ます。図はヒントを2回押したときに出るだけです。

**提案**：式の代わりに、10の枠（緑の丸8個・白2個）だけを見せて問う型を足す。
- 問い①「緑は いくつ？」→ 8
- 問い②「白は いくつ？」→ 2
- 問い③（慣れてきたら）「10に するには あと いくつ？」と、図と式を並べる

画面のイメージ：
```
  10に するには あと いくつ？
  ┌───────────────┐
  │ ● ● ● ● ●     │
  │ ● ● ● ○ ○     │
  └───────────────┘
        [   ]  答える
```

**決まりごと**
- 丸を見せる時間は限らない（ちらっと見せてかくす、は入れない）
- 上の段5個・下の段の形がひと目で分かるよう、C-3のすき間とセットにする
- 出す数は5〜9から（「5といくつ」で見やすい範囲）。1〜4は今のLEVEL 1で十分

**入れる場所**：LEVEL 1の型に足す。あわせて、LEVEL 3の最初の2問（今は「10といくつ」と「繰り下がりなしの引き算」で固定。「5. 小さな気づき」参照）のうち1問を、この型に置きかえる。毎回の「準備運動」として、かたまりを見る目を温めてから10をまたぐ計算に入れる。

**直す場所（ChatGPT向け）**：engine.js に新しい型（例：`frameSee`）を足す。保存データは、型ごとの記録が増えるだけ。旧記録には新しい型の欄がないので、読み込み時に0で足す（保存キー・version 3 はそのまま。A-2の `firstCorrectStreak` と同じ考え方で、古い記録を壊さない）。

### I-2 ★★★ 丸を自分で動かす補助（10をこえる足し算）

**今の作り**：8＋5を間違えると、補助は「8に あといくつで10？」→「5は 2と いくつ？」→「10＋3」の3ステップ。どれも数字で答える問いで、図は止まった絵です。

**提案**：補助の1ステップ目の前に、「丸をうつす」ステップを1つ足す。
1. 画面に、10の枠（緑8個＋白2個）と、となりに オレンジの丸5個を出す
2. 「オレンジを 1こずつ、白いところへ うつそう」。オレンジの丸をタップすると、1個ずつ枠の白いところへ移る
3. 枠がいっぱいになったら、「10に なった！ のこりは？」と聞く → 3
4. そのあと「だから 8＋5は？」→ 13

画面のイメージ（2個うつしたあと）：
```
  ┌───────────────┐
  │ ● ● ● ● ●     │     10に なった！
  │ ● ● ● ◆ ◆     │
  └───────────────┘
   ◆ ◆ ◆           ← のこり 3
```

**ねらい**：「5を2と3に分ける」を言葉で説明する代わりに、「2個うつしたら10になって、3個のこった」を自分の指でやる。分けた結果が、あとから数字の式（ヒント3段階目の `8 ＋ 2 ＝ 10。5の のこりは3。`）と結びつく。

**決まりごと**
- 動きは「タップすると1個移る」だけ。ドラッグ（指でひっぱる）は小さい画面で失敗しやすいので使わない
- 「動きを減らす」設定のときは、移る動きなしで、丸が入れかわるだけにする
- このステップは答えをまちがえることがない（タップするだけ）。記録には数えない
- 絵のタッチ・色は今の10の枠のまま（緑・オレンジ・白の丸）

**のちの使い道**：同じ仕掛けを、ヒントの2段階目（図）でも使える。ヒントで図を出すとき、「うつしてみる」ボタンを添える。

**引き算（減加法）でも**：14−8なら、「10の枠から8個をタップして消す → 2個のこる → となりの4個と あわせる」と、同じ「自分で動かす」形にできる。減加法の流れ（CLAUDE.md の決まり）どおりで、マイナスの説明は使わない。

### I-3 ★★☆ となりの数のちがい（1しか差がない引き算の前段階）

**今の作り**：数の線は LEVEL 1 の「大小」「順番」にだけ使われています。13−12 のような「ひく数が大きくて、答えが小さい」引き算は、今の出題ではほとんど出ません（「繰り下がりなしの引き算」は 15−4 のように、ひく数が1けた）。

**提案**：数の線（今の1〜10の線を、11〜20にも広げたもの）で、2つの数に色をつけて問う型を足す。
- 問い①「13と12、どっちが大きい？」（LEVEL 1の大小と同じ）
- 問い②「13と12は いくつ ちがう？」→ 1。数の線で、となり同士なのが見える
- 問い③（慣れてきたら）「13 − 12 ＝ □」。補助では②に戻る

**ねらい**：近い数どうしの引き算は、「12個とる」と考えると大変だが、「となりだから1」と見れば一瞬。「ひき算＝とる」だけでなく「ひき算＝ちがい」という見方も持てるようにする。

**範囲**：20以内。答えは1〜3（となり・2つとなり・3つとなり）にしぼる。10をまたぐ組み合わせ（11−9 など）は減加法の型に任せ、ここでは扱わない（教え方がまざらないように）。

### I-4 ★☆☆ 5のまとまりで考える足し算（**要相談**）

7＋5は、「7は5と2」「5と5で10」「のこり2で12」と、**5のかたまりどうしを合わせる**考え方もできます。10の枠の上の段（5個）がそのまま見えるので、「7を2と5に分ける」より目で分かりやすい子もいます。

ただし、学校の足し算の教え方（前の数を10にする／後ろの数を10にする）と違うので、**要相談**です。引き算を減加法にそろえたときと同じく、まず学校でどう教えているかを確かめてから決めるのがおすすめです。採用する場合も、補助の1つの見方として出すだけにし、今の「10をつくる」流れは変えません。

### I-5 ★★☆ 家でできること（アプリの変更なし）

アプリより、手で物を動かすほうが早く身につく段階です。どれも数分でできます。
